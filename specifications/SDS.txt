Interior Design Recommendator SDS
Software Design Specification | Version 2.0 | 9 October 2026
1 Introduction
Purpose and scope
SRS 2.0 and Level 0–2 DFDs define a 2,000+ product store with interior AI and separate support chat. Scope: variants/search, accounts, wishlist/cart, orders, private designs and admin. Prototype: demo orders/local overlay; real services require integrations. Future: multi-item preview, mobile, subscriptions, AR/3D. PKR; Asia/Karachi reset.
Users and access

2 System Architecture
Architectural style
React/TypeScript/Vite/Tailwind presents the site; Supabase Auth verifies identity, PostgreSQL stores relational data and Storage separates public products/private rooms. Edge Functions/SQL enforce sensitive operations. AI adapters isolate providers; models never authorize, price, allocate stock or verify payment.

Figure 1  Application architecture and integration boundaries
Processing and deployment boundaries
Commit jobs before HTTP 202. Scheduled/local processors use leases, provider IDs and bounded retries within runtime limits; background functions alone are not durable queues. Bound image decoding/metadata removal before hosted uploads. Browser gets public settings/session; server retains privileged/provider keys.
Deployment and operations
Deploy Vite, migrations/RLS, separate buckets, secret-configured functions and protected job/search/cleanup schedules. Start with demos/overlay; verify credentials, capacity, ownership and failures before enabling integrations. Log IDs/states/retries/once-only transitions; monitor queue age/errors/cleanup/cap. Document database/media recovery; test isolated restore. No automatic paid fallback.

4 Database Design
UUID primary keys, foreign keys and UTC timestamps identify records; private storage object keys replace public room URLs.

Policies and operations
Policies, settings, audit, consent, search outbox and cleanup store approved knowledge, actors, configuration, retries and expiry work.
Relationships and normalization
Category–Product, Product–Variant, Room–Asset and Order–Item are one-to-many. OrderItem links variants; ProductStyle/SavedDesignAsset link styles/assets. Masters use 3NF; order snapshots preserve confirmed values.
Constraints and database objects
Require quantities >0, nonnegative money and stock, reserved stock no greater than on-hand stock, valid states and unique request keys per owner and operation. Use integer minor units for money and decimal centimeters for dimensions. Archive catalogue records without deleting order history.
Protected SQL atomically enforces quota, checkout and stock; updated_at stamps changes. Catalogue writes include audit/search outbox. Public views expose approved fields; owner summaries retain RLS. Index SKU/search, owner+created_at, job state/lease and asset expiry. ProductMedia/Style/GuestSession support core records.
5 Interior Design and Preview Workflows
Room intake and matching
Require processing consent. Accept up to three JPEG/PNG/WebP photos, ≤10 MB and 20 megapixels each; validate actual bytes/decoding, strip unnecessary metadata, assign owner/expiry and choose one base. Photos do not establish measured dimensions. Enabled vision reports uncertain visible features; otherwise use entered preferences.
Shared quota and job state

Figure 2  Persisted preview states and credit finalization
Both entry points share exact-variant previews. Guests: three total; accounts: initially ten/day when capacity permits. Compute Asia/Karachi midnight; store UTC windows; in-flight jobs retain original window. Available=max(0,limit−consumed−reserved). Text/support/samples/overlays use no image credits; local drag/resize/rotate requires no upload. Show mode/credits/reset/sign-up/illustrative notice. Disabled rendering reserves nothing.
Reservation transaction
Verify owner, room, variant, consent, mode and cap/pause. Resolve duplicate key; changed input conflicts. Lock quota window; reject exhaustion; atomically insert QUEUED job/RESERVED entry. Regeneration needs new key.
Execution and finalization
Lease job; persist provider ID; submit permitted room/variant/placement. Poll or verify callbacks; reconcile uncertain outcomes before retry. Store private output; atomically finalize success/CONSUMED or failure/cancel/expiry/RELEASED once, despite duplicates.
Fallback and asset lifecycle
Delete unsaved sources after terminal processing; abandoned sources/unsaved previews expire within 24 hours. Owners save selected unexpired assets privately. Delete/expiry blocks access, cancels jobs and retries derivative cleanup. Recheck before publication; discard late results. Successful credits stay consumed; deleted sources require reupload.

API contract
Routes use Supabase /functions/v1; Auth uses its SDK. Shared schemas validate JSON. Verified sessions determine identity, never browser owner_id; responses include request ID/safe error code.

Checkout and inventory transaction
Quote live prices/quantities/delivery/charges/discounts; customer confirms. Transaction resolves key, locks variants in stable order, rechecks stock/totals and creates immutable lines/reservations once. Conflicts abort for review. Available=on-hand−active reservations; uniquely keyed policy actions commit/release stock once. Separate payment/fulfillment; verified events/authorized COD establish payment. Label demos; collect no card details.
Errors and recovery
Errors: 400/422 invalid input; 401 missing identity; 403 denied access; 404 inaccessible record; 409 price/stock/key conflict; 429 quota/abuse; 503 paused/unavailable integration. Quota errors include remaining/reset/sign-up guidance. Roll back failures and log safe request IDs without secrets/room content.
7 Security Deployment and Verification
Security and privacy controls
Use HTTPS, validation, parameterized access and private-data/storage RLS. Anonymous Auth uses authenticated role: check anonymous status/owner. Customers are owner-scoped; admins require server role, active status/MFA. Restrict/authorize SQL routines; fix search_path. Server holds secrets; prompts/retrieval use read-only allowlists. Check room owner/expiry/deletion; disable private caching. Separate consents/honor withdrawal; enforce abuse limits/global cap.
